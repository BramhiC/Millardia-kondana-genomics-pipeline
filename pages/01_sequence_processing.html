Sequence Processing

This section describes the preprocessing workflow used for Illumina paired-end whole-genome sequencing data of Millardia kondana and Millardia meltada. The aim is to convert raw FASTQ files into high-quality, duplicate-marked, indexed BAM files and a filtered SNP dataset for downstream population genomic analyses.

Input Data

The dataset contains four plateau populations of M. kondana and one comparison population of M. meltada.

  • Sinhagad: K1–K25
  • Rajgad: R1–R25
  • Torna: T1–T25
  • Raireshwar: RR1–RR20
  • M. meltada: MEL1–MEL10

Each sample consists of paired-end Illumina reads. 

K1_R1.fastq.gz
K1_R2.fastq.gz

Software Installation

The analysis was performed in a dedicated conda environment. 

conda create -n mkondana_wgs -y
conda activate mkondana_wgs

conda install -c bioconda fastqc multiqc fastp bwa-mem2 samtools bcftools gatk4 plink -y

This installs all software required for read processing, mapping, duplicate marking and variant calling.

Step 1: Quality Assessment of Raw Reads

Before any processing, the quality of the raw sequencing reads is checked using FastQC. This helps identify adapter contamination, low-quality bases, abnormal GC content and other sequencing issues. 

mkdir -p fastqc_raw

fastqc raw_fastq/*.fastq.gz \
-o fastqc_raw \
-t 16

Because there are many samples, MultiQC is used to combine all FastQC reports into a single summary. 

multiqc fastqc_raw -o multiqc_raw

What to expect

  • Most bases should have quality scores above Q30.
  • Adapter contamination may be present at read ends.
  • Per-base quality often decreases slightly toward the 3′ end.

The MultiQC report is used to decide whether trimming is required.

Step 2: Adapter and Quality Trimming

Illumina reads can contain residual adapter sequences and low-quality bases. These can reduce mapping accuracy and increase false variant calls. fastp is used to trim adapters and filter poor-quality regions. 

mkdir -p trimmed

for sample in K1 K2 K3 R1 R2 T1 RR1 MEL1
do
  fastp \
    -i raw_fastq/${sample}_R1.fastq.gz \
    -I raw_fastq/${sample}_R2.fastq.gz \
    -o trimmed/${sample}_R1.trim.fastq.gz \
    -O trimmed/${sample}_R2.trim.fastq.gz \
    -h trimmed/${sample}.html \
    -j trimmed/${sample}.json \
    --detect_adapter_for_pe \
    --thread 16
done

The same command is repeated for all samples.

What files are produced

  • Trimmed paired FASTQ files
  • HTML report for each sample
  • JSON summary for each sample

What to expect

  • Adapter content should decrease substantially.
  • Average read quality should improve.
  • A small fraction of reads may be removed.

Step 3: Quality Check After Trimming

FastQC is run again to confirm that trimming improved the data and that no major quality problems remain. 

mkdir -p fastqc_trimmed

fastqc trimmed/*.fastq.gz \
-o fastqc_trimmed \
-t 16

multiqc fastqc_trimmed -o multiqc_trimmed

What to expect

  • Adapter warnings should largely disappear.
  • Per-base quality should remain high across most of the read.
  • These trimmed FASTQ files are used for mapping.

Step 4: Prepare the Reference Genome

Because M. kondana does not currently have a species-specific reference genome, reads are aligned to the Rattus rattus reference genome.

Download the reference genome and place it in the reference/ directory. 

mkdir -p reference
cd reference

Reference file: 

Rrattus.fa

The reference must be indexed for BWA, SAMtools and GATK. 

bwa-mem2 index Rrattus.fa

samtools faidx Rrattus.fa

gatk CreateSequenceDictionary \
-R Rrattus.fa \
-O Rrattus.dict

What to expect

  • BWA index files
  • Rrattus.fa.fai
  • Rrattus.dict

These files are required for mapping and variant calling.

Step 5: Read Mapping

Trimmed reads are aligned to the reference genome using BWA-MEM2. This step determines where each read most likely originated in the genome. 

mkdir -p alignment

for sample in K1 K2 K3 R1 R2 T1 RR1 MEL1
do
  bwa-mem2 mem \
    -t 16 \
    reference/Rrattus.fa \
    trimmed/${sample}_R1.trim.fastq.gz \
    trimmed/${sample}_R2.trim.fastq.gz \
    > alignment/${sample}.sam
done

What to expect

  • One SAM file per sample.
  • Mapping rates should generally be above ~80%.
  • Lower mapping may occur because a related species reference is being used.

Step 6: Convert and Sort BAM Files

SAM files are large text files. They are converted into compressed BAM format and sorted by genomic position, which is required for duplicate marking and variant calling. 

mkdir -p bam

for sample in K1 K2 K3 R1 R2 T1 RR1 MEL1
do
  samtools sort \
    -@ 16 \
    -o bam/${sample}.sorted.bam \
    alignment/${sample}.sam

  samtools index bam/${sample}.sorted.bam
done

What to expect

  • Sorted BAM file
  • BAM index file (.bai)

Step 7: Mark PCR Duplicates

PCR amplification during library preparation can produce duplicate reads. These are marked so that they do not bias variant calling. 

mkdir -p stats

for sample in K1 K2 K3 R1 R2 T1 RR1 MEL1
do
  gatk MarkDuplicates \
    -I bam/${sample}.sorted.bam \
    -O bam/${sample}.dedup.bam \
    -M stats/${sample}.dup_metrics.txt

  samtools index bam/${sample}.dedup.bam
done

What to expect

  • Duplicate-marked BAM file
  • Duplicate metrics file
  • Indexed BAM

The duplicate-marked BAM is the version used for downstream analyses.

Step 8: Alignment Statistics

Basic mapping statistics are generated to evaluate the quality of each alignment. 

for sample in K1 K2 K3 R1 R2 T1 RR1 MEL1
do
  samtools flagstat bam/${sample}.dedup.bam \
    > stats/${sample}.flagstat

  samtools stats bam/${sample}.dedup.bam \
    > stats/${sample}.stats
done

Check for

  • Total mapped reads
  • Properly paired reads
  • Duplicate percentage
  • Overall alignment quality

Step 9: Mean Coverage Estimation

Coverage is calculated to determine whether samples have sufficient depth for population genomic analyses and PSMC. 

for sample in K1 K2 K3 R1 R2 T1 RR1 MEL1
do
  samtools depth -a bam/${sample}.dedup.bam | \
  awk '{sum+=$3} END {print sum/NR}' \
  > stats/${sample}.mean_coverage.txt
done

What to expect

  • Mean coverage for each sample.
  • Samples with the highest coverage can later be selected for PSMC.

Step 10: Create BAM List

A text file containing all BAM paths is created for joint variant calling. 

ls bam/*.dedup.bam > bamlist.txt

Step 11: Joint Variant Calling

Variants are called across all samples together using bcftools. Joint calling helps identify shared and population-specific variants consistently. 

mkdir -p variants

bcftools mpileup \
-f reference/Rrattus.fa \
-b bamlist.txt \
-Ou \
-q 20 \
-Q 20 \
-a AD,DP | \
bcftools call \
-m -v -Ou | \
bcftools norm -f reference/Rrattus.fa -Oz \
-o variants/variants.raw.vcf.gz

bcftools index variants/variants.raw.vcf.gz

What to expect

  • Raw VCF containing SNPs and INDELs.
  • This dataset still contains low-quality and rare variants.

Step 12: Retain SNPs Only

INDELs are removed because the downstream analyses in this pipeline use SNPs. 

bcftools view -v snps \
variants/variants.raw.vcf.gz \
-Oz -o variants/variants.snps.vcf.gz

Step 13: Quality Filtering

Variants with low confidence are removed using a minimum QUAL score of 20. 

bcftools filter -i 'QUAL>20' \
variants/variants.snps.vcf.gz \
-Oz -o variants/variants.qual20.vcf.gz

Step 14: Remove Rare Variants

Variants with very low allele counts can be unreliable and may add noise to population structure analyses. A minimum minor allele count (MAC) of 3 is used. 

bcftools view -i 'MAC>3' \
variants/variants.qual20.vcf.gz \
-Oz -o variants/variants.mac3.vcf.gz

Step 15: Hardy–Weinberg Filtering

Variants with strong deviation from Hardy–Weinberg equilibrium are removed. This helps reduce potential genotyping errors and problematic sites. 

bcftools +fill-tags variants/variants.mac3.vcf.gz -- -t HWE | \
bcftools view -i 'HWE>0.05' \
-Oz -o variants/variants.filtered.vcf.gz

bcftools index variants/variants.filtered.vcf.gz
